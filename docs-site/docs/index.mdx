Cette documentation s'adresse aux équipes techniques qui connectent leur backend à TrustSend. Elle décrit les endpoints accessibles avec une clé API business, leurs paramètres, leurs réponses et les erreurs à gérer.

## Avant de commencer

- Un **compte business TrustSend** vérifié et activé, ouvert depuis l'[Espace client](https://business.trustsend.africa).
- Une **clé API**, générée depuis l'Espace client — voir [Authentification](/authentication).
- Un **endpoint HTTPS** sur votre serveur pour recevoir les [webhooks](/webhooks).

## Principes de l'API

### Requêtes et réponses

Les requêtes et les réponses sont au format JSON, encodées en UTF-8. Envoyez l'en-tête `Content-Type: application/json` avec chaque requête comportant un corps.

Une réponse réussie place la ressource dans un champ `data`. Une erreur renvoie un champ `message` — voir [Erreurs](/errors).

```json
{ "data": { "id": 38, "currency_code": "CDF", "balance": "0" } }
```

### Montants

Les montants sont exprimés dans la **plus petite unité de la devise** et transmis sous forme de chaîne de caractères, afin d'éviter toute perte de précision liée aux nombres décimaux.

```json
{ "amount": "50000", "currency_code": "USD" }
```

Dans cet exemple, `"50000"` correspond à 500,00 USD.

### Idempotence

Les opérations qui déplacent des fonds exigent une `idempotency_key` au format UUID, unique pour chaque tentative. Si une requête est rejouée avec la même clé — après un délai d'attente dépassé par exemple — l'API renvoie le résultat de la première tentative au lieu de créer une nouvelle opération.

Réutiliser une clé avec un contenu de requête différent renvoie `409`.

### Opérations asynchrones

Les dépôts et les retraits sont traités de façon asynchrone. L'API répond immédiatement `202` avec une opération au statut `processing`, puis vous notifie de son résultat final par [webhook](/webhooks).

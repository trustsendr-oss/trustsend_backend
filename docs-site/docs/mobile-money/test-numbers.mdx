# Numéros de test (sandbox)

En [sandbox](/sandbox), les dépôts et retraits mobile money passent par l'environnement de test. Certains numéros de téléphone y produisent un résultat connu d'avance : réussite, échec avec un code précis, ou opération qui reste en attente. Ils permettent de vérifier que votre intégration gère chaque cas.

:::warning
 Sandbox uniquement
Ces numéros ne fonctionnent que sur l'API sandbox (`https://sandbox-api.trustsend.africa/api/v1`). En production, ils ne correspondent à aucun client réel.
:::
## Utiliser un numéro de test

Envoyez un [dépôt ou un retrait](/mobile-money/deposits-payouts) avec le numéro de test dans `phone_number` et le code opérateur correspondant dans `provider`. La devise doit être acceptée par cet opérateur : consultez [Moyens de paiement](/mobile-money/payment-methods).

```bash
curl -X POST https://sandbox-api.trustsend.africa/api/v1/business/mobile-money/deposits \
  -H "Authorization: Bearer $TRUSTSEND_SANDBOX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": "50000",
    "currency_code": "CDF",
    "phone_number": "243813456789",
    "provider": "VODACOM_MPESA_COD",
    "idempotency_key": "4f6b1c2e-8a8d-4c1e-9d0a-2b7e5f3c9a11",
    "pin": "0000"
  }'
```

En sandbox, le client n'a pas à valider le paiement sur son téléphone : le résultat arrive plus vite qu'en production.

## Résultats

| Résultat indiqué | Ce que vous observez |
|---|---|
| Réussi | La transaction passe à `completed` et le webhook `.completed` est envoyé |
| Échec | La transaction passe à `failed`, le webhook `.failed` est envoyé et le motif figure dans `failure_reason` |
| Reste en attente | La transaction reste `processing` : utile pour tester l'affichage d'une opération en cours |

## Codes d'échec

| Code | Opération | Signification |
|---|---|---|
| `PAYER_NOT_FOUND` | Dépôt | Le numéro du payeur n'est pas reconnu par l'opérateur. |
| `PAYMENT_NOT_APPROVED` | Dépôt | Le client n'a pas autorisé le paiement, par exemple faute d'avoir saisi son code PIN à temps. |
| `INSUFFICIENT_BALANCE` | Dépôt, retrait | Solde insuffisant pour effectuer l'opération. |
| `PAYER_LIMIT_REACHED` | Dépôt | Le payeur a atteint une limite de son compte mobile money. |
| `TRANSACTION_ALREADY_IN_PROCESS` | Dépôt | Une autre transaction du client est déjà en cours chez l'opérateur. |
| `RECIPIENT_NOT_FOUND` | Retrait | Le numéro du bénéficiaire n'appartient pas à l'opérateur indiqué. |
| `WALLET_LIMIT_REACHED` | Retrait | Le bénéficiaire a atteint une limite de son compte, par exemple un plafond hebdomadaire. |
| `RECIPIENT_LIMIT_REACHED` | Retrait | Le bénéficiaire a atteint une limite de réception. |
| `PAYEE_LIMIT_REACHED` | Retrait | Le bénéficiaire a atteint une limite de réception. |
| `PAYEE_NOT_ALLOWED_TO_RECEIVE` | Retrait | Le compte du bénéficiaire n'est pas autorisé à recevoir des fonds. |
| `PO_MAX_AMOUNT_DAY` | Retrait | Le montant maximal de retraits pour la journée est atteint. |
| `UNSPECIFIED_FAILURE` | Dépôt, retrait | L'opérateur n'a pas indiqué la raison de l'échec. |
